# Droply Protocol v1.1 Specification

## 1. Overview
Droply transfers files, text notes, and directory trees directly over local Wi-Fi (LAN) via a single full-duplex TCP connection. Both Android and macOS can send and receive files, folders, and text with explicit recipient confirmation.

## 2. QR Code Payload (UTF-8 JSON)
Generated by the MacBook host and scanned by the Android device:
```json
{
  "v": 1,
  "host": "192.168.1.42",
  "hosts": ["192.168.1.42"],
  "port": 45820,
  "token": "a1b2c3d4e5f60718293a4b5c6d7e8f90",
  "name": "MacBook Pro"
}
```

## 3. Binary Wire Framing
Every message on the TCP stream uses a 5-byte header followed by `length` payload bytes:

| Offset | Size | Type | Description |
|--------|------|------|-------------|
| 0 | 1 byte | `UInt8` | Frame type ID |
| 1 | 4 bytes | `UInt32` (big-endian) | Payload length in bytes (`N`) |
| 5 | `N` bytes | `Bytes` | Frame payload (UTF-8 JSON or raw binary chunk) |

### Frame Types
- `0x01` `HELLO` (Client -> Server): `{"token": "...", "deviceName": "CPH2707"}`
- `0x02` `HELLO_ACK` (Server -> Client): `{"ok": true, "deviceName": "MacBook Pro", "error": null}`
- `0x03` `BATCH_START` (Sender -> Receiver): `{"batchId": "uuid", "totalFiles": 12, "totalBytes": 104857600, "previewName": "photo.jpg"}`
- `0x04` `FILE_START` (Sender -> Receiver): `{"fileIndex": 0, "relativePath": "Trip/photo.jpg", "size": 5242880, "isText": false}`
- `0x05` `FILE_CHUNK` (Sender -> Receiver): Raw binary file bytes (`262144` bytes / 256 KB).
- `0x06` `FILE_END` (Sender -> Receiver): `{"sha256": "<64-char lowercase hex>"}`
- `0x07` `PROGRESS_ACK` (Receiver -> Sender): `{"fileIndex": 0, "fileBytesReceived": 2097152, "batchBytesReceived": 2097152, "totalBytes": 104857600, "percent": 2.0}`
- `0x08` `FILE_RESULT` (Receiver -> Sender): `{"fileIndex": 0, "ok": true, "savedPath": "...", "error": null}`
- `0x09` `BATCH_END` (Sender -> Receiver): `{"batchId": "uuid"}`
- `0x0A` `CANCEL` (Bidirectional): `{"reason": "Cancelled by user", "target": "incoming|outgoing|any"}`
- `0x0B` `DISCONNECT` (Bidirectional): `{}`
- `0x0C` `PING` / `0x0D` `PONG`: `{}`
- `0x0E` `BATCH_ACCEPT` (Receiver -> Sender): `{"batchId": "uuid", "accepted": true, "reason": null}`
